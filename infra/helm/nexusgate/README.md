# NexusGate Helm chart

Installs the gateway on a real Kubernetes cluster: the API and the ingestion workers, with Redis and
Qdrant either bundled or external, and monitoring handed to the cluster's own Prometheus Operator.

```bash
helm install nexusgate infra/helm/nexusgate --namespace nexusgate --create-namespace \
  --set image.repository=<your-registry>/nexusgate-api --set image.tag=<tag> \
  --set secrets.existingSecret=nexusgate-secrets
```

The defaults mirror [`infra/k8s/base`](../../k8s/base), which is the stack the load, soak and chaos
tests ran against. The kustomize stack is still the way to run everything on one laptop; this chart
is the way to run it on a cluster you don't own end to end.

## What differs from the laptop stack, and why

| | Laptop stack (kustomize) | This chart |
|---|---|---|
| Prometheus, Grafana, Alertmanager | bundled, so the stack is self-contained | not shipped — a cluster already runs them. A `ServiceMonitor`, a `PrometheusRule` and a dashboard `ConfigMap` plug into the Prometheus Operator instead |
| Redis, Qdrant | always bundled | bundled by default, or `enabled: false` plus an `externalUrl` for a managed service |
| Secrets | generated by `cluster-up` from `.env` | your own Secret (`existingSecret`), or values the chart refuses to install without |
| Worker autoscaling | on, with prometheus-adapter bundled | off by default: it needs an adapter serving the queue-depth metric, which is cluster-specific |
| PodDisruptionBudget | none | on for the API, so a node drain can't evict every replica at once |
| Config changes | roll pods via hashed ConfigMap names | roll pods via a checksum annotation |

## Secrets

Nothing has a default. The app refuses default secrets in production, so the chart refuses to
render without them and says which one is missing:

```
Error: execution error at ...: secrets.adminToken is required (or set secrets.existingSecret)
```

Either point at a Secret you manage — sealed-secrets, external-secrets, or `kubectl create secret`
— carrying `NEXUSGATE_ADMIN_TOKEN`, `NEXUSGATE_JWT_SECRET` (32+ characters),
`NEXUSGATE_QDRANT_API_KEY` and optionally `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`:

```yaml
secrets:
  existingSecret: nexusgate-secrets
```

or pass `secrets.adminToken`, `secrets.jwtSecret` and `secrets.qdrantApiKey` and the chart creates
one. Values files are not where production secrets belong; the second form is for trying it out.

## External datastores

```yaml
redis:
  enabled: false
  externalUrl: rediss://:password@my-redis.example:6380/0
qdrant:
  enabled: false
  externalUrl: https://my-cluster.qdrant.io:6333
```

The semantic cache's `redisearch` index needs Redis Stack's Query Engine. On plain Redis, set
`config.NEXUSGATE_CACHE_INDEX_BACKEND: bruteforce`. Disabling a datastore without an `externalUrl`
is refused at render time rather than producing pods that cannot start.

## Monitoring

```yaml
metrics:
  serviceMonitor: { enabled: true, labels: { release: kube-prometheus-stack } }
  prometheusRule: { enabled: true }
  grafanaDashboard: { enabled: true }
```

The `ServiceMonitor` scrapes each API pod separately — every replica keeps its own counters — and
relabels them to `job="nexusgate-api"`, the job name the alert rules and the load-test tooling select
on. The rules and dashboard are the same files the laptop stack loads; a test fails if the chart's
copies ever drift from them.

## Autoscaling

The API scales on CPU, which the load test showed is the ceiling once inference is bounded, with a
two-minute scale-up window because a new pod's model loading reads as load. The workers scale on
**queue depth, not CPU** — one ingest job saturates a worker's CPU with nothing waiting — which needs
prometheus-adapter serving `nexusgate_ingest_queue_depth` (the rule is in
[`infra/k8s/base/config/prometheus-adapter.yaml`](../../k8s/base/config/prometheus-adapter.yaml)).

## Settings

Everything under `config` becomes an environment variable on every pod, so any `NEXUSGATE_*`
setting from [`.env.example`](../../../.env.example) can go there. The defaults carry the choices the
evals and load tests made: hybrid retrieval with rank fusion, 12 rerank candidates, and circuit state
shared across replicas.

## Validation

- `tests/unit/test_helm_chart.py` renders the chart and checks what it produces and what it refuses:
  missing or short secrets, a disabled datastore with nowhere to point, the HPA owning the replica
  count, no disruption budget on a single replica, config changes rolling the pods, non-root
  containers everywhere.
- CI lints it and validates every rendered object with `kubeconform -strict`, including the Prometheus
  Operator CRDs, with every optional piece switched on (`ci/test-values.yaml`).
- It has been installed into a kind cluster with its defaults and passed the full
  [`smoke test`](../../../scripts/smoke_test.py): chat, caching, fallback, shared breaker state,
  streaming, canary rollout, RAG ingestion through the workers, search, answers and the agent.
